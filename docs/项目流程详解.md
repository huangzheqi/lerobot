## 1. 项目一句话定位

> 用强化学习(PPO 算法)训练 SO-ARM101 这只 5 自由度机械臂,在 Isaac Lab 仿真里学会「把桌面上的方块抓起来,搬到指定位置」。最终目标是迁移到**真实**的 SO101 机械臂,用**摄像头视觉**来定位方块。

技术栈分层:

```
任务逻辑   ← 本仓库 isaac_so_arm101 (奖励、观测、场景、机器人定义)

仿真引擎   ← Isaac Lab / Isaac Sim (物理、渲染、相机)
环境接口   ← Gymnasium (把任务注册成标准的 env,可 reset/step)
语言/包管理 ← Python 3.11 + uv
```

## 2. 强化学习基础(落到本项目)

强化学习的标准框架叫 **MDP(马尔可夫决策过程)**,核心是一个循环:

```
        ┌──────────────────────────────────────────┐
        │                                            │
   观测 obs ──▶ 策略 policy(神经网络) ──▶ 动作 action ─┘
        ▲                                            │
        │                                            ▼
     环境 environment ◀───────────────────── 执行动作、物理推进一步
        │
        └──▶ 奖励 reward(打分,告诉策略刚才做得好不好)
```

本项目里这些概念分别是:

| RL 概念 | 本项目里是什么 | 在哪定义 |
|---|---|---|
| **环境 env** | 桌子 + 机械臂 + 方块 + 目标点的仿真场景 | `lift_env_cfg.py` 的 `ObjectTableSceneCfg` |
| **观测 observation** | 机械臂关节状态 + 方块位置 + 目标位置 + 上一步动作 | `ObservationsCfg.PolicyCfg` (第 4 章) |
| **动作 action** | 5 个手臂关节的目标角度 + 夹爪开/合 | `ActionsCfg` (第 4 章) |
| **奖励 reward** | 一组打分函数的加权和(靠近、抓起、搬运、放下…) | `rewards.py` + cfg (第 5 章) |
| **策略 policy** | 一个 MLP 神经网络(输入观测,输出动作) | RSL-RL 的 ActorCritic |
| **回合 episode** | 一次「从复位到 5 秒结束」的完整尝试 | `episode_length_s=5.0` |
| **终止 termination** | 超时 或 方块掉到桌下 | `TerminationsCfg` |

**节拍换算(回答"250 是怎么来的"):**
`lift_env_cfg.py:234-238` → 物理步长 `sim.dt=0.01`(100Hz),`decimation=2`(每 2 个物理步策略决策一次)→ **策略控制频率 50Hz**;回合 5 秒 → **每回合 250 步**。这正是训练日志里 `Mean episode length: 250.00` 的来历。

## 3. ★最关键的认知:训练时和推理时是两条不同的数据流★

很多困惑都源于把这两条流混在一起。请务必分清:

### 3a. 训练时(`train.py`)—— 没有摄像头!

训练时方块的位置是**仿真器直接给的真值(Ground Truth)**,根本不经过相机和图像识别。原因:训练要在 4096 个并行环境里高速跑上亿步,渲染几千张图片再做视觉太慢、也没必要。

```
仿真器(物理引擎)
   │  直接读出方块的真实坐标
   ▼
观测 obs(含方块真值位置)──▶ 策略网络 ──▶ 动作 ──▶ 物理推进 ──▶ 奖励
   ▲                                                          │
   └───────────────────── 收集 (obs, action, reward) ◀────────┘
                                  │
                                  ▼
                          PPO 更新策略网络权重
```

所以**训练产出的策略,本质是「给我方块的 xyz 坐标,我就输出关节动作去抓」**。它并不认识图像,它只认识坐标。

### 3b. 推理/播放时(`play.py`)—— 这时才有摄像头

部署/观测模型时,我们用 `--object_pose_source` 选方块坐标从哪来:

| 模式 | 方块坐标来源 | 用途 |
|---|---|---|
| `gt` | 仿真真值(和训练一样) | 看策略本身的上限 |
| `vision` | **固定相机拍图 → 红色掩码识别 → 反投影算坐标** | 模拟真机视觉 |
| `resnet` | 相机拍图 → ResNet18 神经网络回归坐标 | 另一种视觉方案 |

**关键点:无论哪种模式,识别出的方块坐标都被塞回观测里那 3 维 `object_position`,策略网络完全不知道这 3 个数字是真值还是相机算的。** 这就是为什么「训练只用真值、推理却能用视觉」——只要视觉把坐标算准,策略就照常工作。

### 3c. 所以你问的"工作顺序"准确答案是:

> **(推理 vision 模式,每个控制周期 20ms 重复一次):**
> 1. 读取训练好的模型文件(`model_26994.pt`)——**只在开头做一次**
> 2. 固定相机拍一张当前画面
> 3. 用颜色掩码识别画面里的红方块,算出它的 xy 坐标
> 4. 把这个坐标写进观测向量的 `object_position` 槽位
> 5. 策略网络读观测 → 输出 6 维动作(5 关节角 + 夹爪)
> 6. 仿真执行动作,机械臂动一下,物理推进
> 7. 回到第 2 步(**每一步都重新拍照、重新识别——是实时闭环,不是开局拍一张**)

第 7 步的"实时"特性正是你之前担心的"方块掉了能不能重新抓"的答案:每步都重新看,所以掉了/被推走了,下一步就能看到新位置继续追。

## 4. 环境定义:观测、动作、目标

### 4a. 观测空间(策略网络的输入)

定义在 `lift_env_cfg.py:117-136`,5 个部分按顺序拼接成一个向量:

| # | 观测项 | 维度 | 含义 |
|---|---|---|---|
| 1 | `joint_pos` (joint_pos_rel) | 6 | 6 个关节当前角度(相对默认姿态) |
| 2 | `joint_vel` (joint_vel_rel) | 6 | 6 个关节角速度 |
| 3 | `object_position` | 3 | **方块在机器人基座坐标系下的 xyz** ← 视觉模式下被覆写的就是这 3 维 |
| 4 | `target_object_position` | 7 | 目标位姿(xyz 位置 + 四元数姿态) |
| 5 | `actions` (last_action) | 6 | 上一步输出的动作 |

合计约 **28 维**。第 3 项(方块位置)是整个视觉方案的"接口":`play.py:333` 用 `object_slice` 精确定位这 3 维的下标,推理时把识别结果写进去。

> 为什么方块位置只有 3 维(xyz)没有姿态?因为抓正方体不需要知道它转了多少度,只要知道它在哪。这也是 v9 策略只需要 xy 准确、对 z 不敏感的原因。

### 4b. 动作空间(策略网络的输出)

定义在 `lift/joint_pos_env_cfg.py:114-125`,共 6 维:

- **手臂(5 维)**:`JointPositionActionCfg`,控制 `shoulder_.*`(2) + `elbow_flex`(1) + `wrist_.*`(2) 这 5 个关节的**目标角度**。`scale=0.5` 表示网络输出乘以 0.5 再加到默认角度上(限制单步幅度,让动作平滑)。
- **夹爪(1 维)**:`BinaryJointPositionActionCfg`,**二值**控制——输出 ≥0 就张开(目标角 0.5),<0 就闭合(目标角 0.0)。

> 注意"位置控制"这个性质:夹爪是去**到达目标角度**,会用足够的力推开挡路的东西。这就是我们之前发现"加重方块也防不住被推走"的根本原因——摩擦力 μmg 抵抗不了位置控制器。

### 4c. 目标点(goal / "box")怎么生成

定义在 `lift_env_cfg.py:92-105` 的 `UniformPoseCommandCfg`。每回合复位时,在这个范围里**随机采样**一个目标位姿:

```
pos_x ∈ (-0.1, 0.1)    pos_y ∈ (-0.3, -0.1)    pos_z ∈ (0.2, 0.35)   (机器人基座坐标系)
```

这个目标会写进观测第 4 项,告诉策略"要把方块搬到哪"。

> 【注意】 一个重要历史坑:`pos_z ∈ (0.2, 0.35)` 是一个**悬空**的目标点(离桌面 20~35cm),从 lift 任务继承来的。这导致用 3D 距离判"是否搬到位"永远失败(方块放在桌上时 z 差着 20cm)。我们的 `funnel_v9.py` 因此改用「XY 距离 + 是否落桌」来判定,详见第 11 章。

### 4d. 复位与终止

- **复位**(`lift_env_cfg.py:145-153`):每回合方块在 `x∈±0.1, y∈±0.2` 范围随机出生(桌面高度 z=0.015)。
- **终止**(`lift_env_cfg.py:187-194`):① `time_out` 超过 5 秒;② `object_dropping` 方块掉到 z<-0.05(桌下)。

## 5. 奖励系统(本项目的核心与难点)

### 5a. 两层结构:lift 基础奖励 被 pick_place 覆盖

奖励分两个文件:

1. **基础层** `lift_env_cfg.py:156-183`(`RewardsCfg`):标准的抓取-搬运奖励(reaching/lifting/goal_tracking + 动作惩罚)。
2. **覆盖层** `pick_place/joint_pos_env_cfg.py:34-148`:在 `__post_init__` 里**把基础层的目标跟踪关掉**(`object_goal_tracking.weight = 0.0`),换成一套**分阶段(staged)** 的精细奖励。

最终生效的总奖励 = 各项 `func` 的输出 × 各自 `weight`,**逐项相加**。这就是"奖励函数怎么连接在一起"的答案:**它们不是串行调用,而是并行打分、加权求和**,每一步算出一个标量总分给 PPO。

### 5b. 基础层奖励公式(lift 复用,来自 isaaclab_tasks)

核对自 isaaclab 标准实现:

| 奖励项 | 公式 | 直觉 |
|---|---|---|
| `reaching_object` | `1 − tanh(d_ee→obj / 0.05)` | 末端越靠近方块,越接近 1 分 |
| `lifting_object` | `1 if z_obj > 0.025 else 0` | 方块被抬离桌面就给 1 分 |
| `object_goal_tracking` | `(z_obj>0.025) · (1 − tanh(d_obj→goal / 0.3))` | 抬起后,越靠近目标越高分(粗) |
| `object_goal_tracking_fine` | 同上但 `std=0.05` | 同上(细,临门一脚) |
| `action_rate` | `−||a_t − a_{t-1}||²` | 惩罚动作突变(让运动平滑) |
| `joint_vel` | `−||关节速度||²` | 惩罚关节乱晃 |

> `tanh(d/std)` 是 RL 里最常见的"距离核":d=0 时为 0(奖励满),d 远大于 std 时趋近 1(奖励趋 0),std 控制"多近才算近"。

> 【图】 **本章配图见 `数据流框图.md` 图6(分阶段奖励结构)**:四个阶段、各自的门控条件、每个奖励项及权重、锁存器,一张图看全。
> 【文档】 **每个奖励函数的核心代码 + 数学公式 + 并行机制**(同时计算? 4096 个是否独立?)见 **`奖励函数详解.md`**。

### 5c. 覆盖层:分阶段门控(staged gating)

`pick_place` 把任务拆成 4 个阶段,用方块的**高度**和**到目标的 XY 距离**当作"闸门"(gate),让每个阶段只激活对应的奖励。核心函数 `rewards.py:186-198` 的 `_gates()`:

```python
is_lifted  = z_obj > 0.045          # 抬起来了吗
near_goal  = xy_dist < 0.06         # 到目标上方了吗
low_height = z_obj < 0.045          # 降下来了吗

s1 = (未抬起)                       # 阶段1:接近+抓取
s2 = (抬起 且 没到目标上方)          # 阶段2:搬运
s3 = (抬起 且 到目标上方 且 还没降)  # 阶段3:下降
s4 = (抬起 且 到目标上方 且 已降下)  # 阶段4:释放
```

每个奖励函数把自己乘以对应的闸门(s1~s4),**不在自己阶段时输出 0**。这样策略在不同阶段收到不同的引导信号,像"流水线"一样被一步步推着完成 抓→搬→放。

### 5d. 覆盖层各奖励项一览(`pick_place/joint_pos_env_cfg.py`)

| 阶段 | 奖励项 | 权重 | 作用 |
|---|---|---|---|
| 1 | `reaching_object` | +1.0 | 靠近方块 |
| 1 | `lifting_object` | +5.0 | 抬起方块 |
| 2 | `stage2_goal_xy_tracking_gated` | +10.0 | 举着方块往目标 XY 走 |
| 2 | `stage2_early_open_penalty_gated` | −5.0 | 搬运途中过早松爪 → 扣分 |
| 3 | `stage3_soft_descent_reward_gated` | +12.0 | 到目标上方后柔和下降 |
| 3 | `stage3_hard_drop_penalty_gated` | −8.0 | 砸下来 → 扣分 |
| 3 | `stage3_ee_low_near_goal_gated` | +14.0 | 末端降到目标附近的低位 |
| 3 | `stage3_object_height_near_table_gated` | +14.0 | 方块降到接近桌面 |
| 3 | `stage3_wrist_flex_release_pose_gated` | +2.0 | 手腕摆成释放姿态 |
| 4 | `stage4_release_reward_gated` | +12.0 | 在释放位张爪 |
| 4 | `stage4_hold_too_long_penalty_gated` | −10.0 | 该放却一直攥着 → 扣分 |
| 4 | `stage4_gripper_open_near_table_gated` | +11.0 | 低位近目标时张爪 |
| 4 | `stage4_stable_placed_reward_gated` | +16.0 | 方块稳稳放在目标 → 大奖励 |
| 4 | `stage4_ee_away_after_place_gated` | +2.0 | 放完手撤离 |
| 全程 | `action_rate`(继承自 lift) | **−0.1** | 惩罚动作突变(平滑) |
| 全程 | `joint_vel`(继承自 lift) | **−0.1** | 惩罚关节乱晃 |

> 【注意】 上表才是**完整的生效奖励集**:除了 15 个分阶段项,还有两个**继承自 lift 基础层的惩罚** `action_rate` / `joint_vel`(基础值 −1e-4,被 curriculum 在 `num_steps=0` 时立即拉到 −0.1)。另有两项被**显式关掉**(权重=0,不生效):`object_goal_tracking`、`object_goal_tracking_fine_grained`(被分阶段奖励取代)。

#### 权重 vs 日志值:别把两者混为一谈

- **权重(表里的数字)** 是设计者设定的**固定常数**,本身没有"范围/理想值",它只表达各阶段的相对优先级(谁更重要)。每步该项实际奖励 = `函数输出 f × 权重 × dt(0.02s)`,逐项求和得到每步总奖励。
- **函数输出 f 的范围**(这才有范围):核函数类(reaching、各 tracking/descent)`∈[0,1]`;指示类(lifting、stable_placed)`∈{0,1}`;惩罚类输出 ≥0 再乘负权重。
- **训练日志里的 `Episode_Reward/<项>`** = 该项在一回合 250 步的累计(再对所有环境取平均)。理论上限 ≈ `权重 × 5`(=权重×dt×250,假设每步满分;实际只在本阶段激活几十步,远小于此)。
- **"理想值"看的是日志值的趋势,不是权重**:正向项(尤其 `lifting_object`)应随训练**上升**并趋向上限;惩罚项应**趋近 0**(坏行为被消除)。训练健康 = 想要的行为升、惩罚归零。

### 5e. 锁存器(latch):防止"拖着方块走"的作弊

`rewards.py:80-107` 的 `_cube_was_lifted_this_episode()` 是一个**每回合一次性触发的开关**:方块只要在本回合里抬起过一次(z>0.045),开关就永久置 1,回合结束才复位。

为什么需要它?因为目标点改低后,策略可能发现一条**捷径**:不抬方块,直接在桌面上把它**推到**目标位置,照样能拿到 stage3/4 的"近目标"奖励。锁存器把所有 stage3/4 奖励乘上"本回合抬起过吗",**没真正抬起就一分拿不到**,堵死了这条捷径。

> 这正是我们 v17~v19 微调实验失败的根源:v9 策略当年训练时还没有这些锁存器,加上锁存后等于改变了奖励地形,微调时 critic(价值网络)失配,导致抓取能力慢慢流失。结论:**收敛的 v9 在改过的奖励地形上不可微调**(详见记忆 `pick-place-v17-training-campaign`)。

### 5f. ★已知设计陷阱:为什么机械臂"抓住不放"(局部最优)★

这是组会最容易被追问的现象:稳定放置阶段,机械臂常常**一直夹着方块不松手**。当年 Codex(GPT)在 v7→v8 的测试结论里把它诊断为「策略陷入"抓住不放"的局部最优」——**这个诊断是对的**。下面把"现象 → 成因 → 解决尝试"三层讲透。

**先纠正一个常见的口头误解**:不是"放置会扣分所以不放"。看代码,放置其实给**大额奖励**:`stage4_release_reward`(+12)、`stage4_gripper_open_near_table`(+11)、`stage4_stable_placed_reward`(+16)。真正的原因是下面两条结构性问题。

**成因①:持续收入流 vs 一次性奖金。** PPO 最大化的是整段回合**折扣累计**的总分,不是单步分。

- "夹着举高"是一个**每步都给分**的状态:`lifting_object`(z>0.025)每步 +5、`reaching_object` 每步 +1,外加 stage3 悬停分。回合还剩 ~100 步,这是一笔 **+6~13/步 × 100 步**的持续收入。
- "放置"是**一次性**事件:松手瞬间拿 release/open/placed 共 ~+40,但松手后方块落桌、z 掉到 0.025 以下,`lifting_object` 那 +5/步的持续收入**立刻归零**,后半段几乎再无进账。
- 两者一比:持续收入的积分 >> 一次性奖金。理性策略选择**一直夹着保住现金流**。

**成因②:目标点设在空中。** `object_pose` 的 `pos_z=(0.2, 0.35)`(`lift_env_cfg.py:100`)——任务目标字面上是桌面上方 20~35cm 的**空中点**。所以"把方块举在空中"在几何上**就等于对准目标**,往桌上放反而是**远离目标**。环境的奖励定义本身就在鼓励"举着"。(这就是反复踩的"空中目标陷阱",见记忆 `pick-place-goal-z-metric-mismatch`。)

**"局部最优"到底是什么意思 —— 一道跨不过的奖励山谷。** 局部最优不是机械臂"想通了不划算",它没有意识。准确含义是:**在当前策略附近,任何微小改动都会让总分变低**,梯度上升停在这里出不去。

```
总分
 ^
 |     /---\     <-「成功放置」高峰(release+open+placed ≈ +40 一次性)
 |    /     \
 |   /  谷   \___  <- 山谷:开始松手 → 立刻丢掉 lifting +5/步的持续收入,
 |  /        但方块还没稳稳落桌、放置奖金还没到手 → 总分先掉下去
 |「夹住不放」(局部最优)
 +------------------------------> 策略往"放下"方向变化
```

要从"夹住"峰走到"放置"峰,策略**必须先穿过中间这道会掉分的山谷**。而 PPO 是**小步梯度上升 + clip 限幅**,只往"立刻能涨分"的方向走;站在"夹住"峰上,梯度指向"夹得更稳",指向放置是**下坡**,它不会走。再加上探索很弱(`entropy_coef=0.0025`),收敛后几乎不可能靠随机噪声连续做出"下降+松手+稳定"一整套动作去**尝到对岸奖金**,也就爬不上另一座山。这就是"放弃后面任务"的真正机制:**不是选择,是梯度被山谷挡住、过不去**。

**解决尝试(v8_curriculum):本质是"填这道山谷"。** 当年 v8 的改动——降低门控阈值(`lift_height` 0.05→0.045、`release_height` 0.05→0.045)、加大 stage3 软着陆奖励(在谷里铺引桥)、加大 stage4 释放/放置奖励并加大 hold-too-long 惩罚(抬高对岸、压低这边)——思路完全正确(标准的 curriculum / reward shaping 填谷法)。但**没能根除**:桌面放置 shaping 到 v14/v15 仍被放弃,最终冻结的 v9 用的是**空中目标**而非桌面放置。根因还是上面两条没断:只要"举着"能持续薅分、目标又在空中,这道谷就会重新长出来。

> 补充一个门控漏洞:反薅的 `stage4_hold_too_long_penalty`(-10)只在 **stage4(lifted & near_goal & low_height)** 触发。机械臂只要**悬在高处**(落在 stage3,不是 stage4),这个惩罚根本不生效——它能靠"举高一点"绕开惩罚继续薅。

**一句话**:GPT 的"局部最优"是现象的正确命名;成因是"持续抬起收入流 + 空中目标"挖出了一道梯度跨不过的奖励山谷;v8 的填谷是对症尝试但没断根。要真正逼出"放下",得从结构上改(目标 z 降到桌面 / 把 `lifting_object` 从持续改成一次性达成即停 / 让 hold 惩罚不依赖低空门控),而这属于改奖励地形,对已收敛的 v9 续训会崩(见 5e),只能从头训。

### 5g. 组会追问串:分阶段课程、奖励上限,能不能打破局部最优?

这是组会上从 5f 顺下来的一连串好问题。结论先放这:**这些直觉都对、都是正确方向,但每一个单独用都治不了"抓住不放",我们大多实测过。**

**① "把每阶段练到满分再进下一阶段(分阶段课程 / curriculum)可行吗?"**

可行的是"精神",不是"硬顺序"。要分两种:

- **硬顺序(练满阶段1 → 关掉 → 练阶段2 …)**:不可行。神经网络会**灾难性遗忘**——练后一阶段时把前一阶段技能忘光(我们 v17–19 续训实测:grasp 44%→0%);而且阶段之间**咬合切不开**(练阶段2需要"方块已夹住"的初始态,从哪来?);单阶段刷满分还常练出对全局有害的姿势(正是"抓住不放")。
- **软课程(不关闭前阶段,逐步累加奖励)**:这才是合理做法,而我们**当前的分阶段门控本质上就是它**——机械臂因物理因果"先学会前阶段",但前阶段奖励**始终开着、不关**。

**② "不关闭前阶段的分,会不会让后阶段刷不满 / 进局部最优?"**

会,而且**"不关闭"恰恰是局部最优的来源**。关键看前阶段奖励**有没有被门控**:

- 我们的 **stage2/3/4 项是门控的**(进别的阶段乘 0,不竞争);
- 但**基础奖励 `reaching`(+1)、`lifting`(+5)是不门控的**,全程每步都发。于是"举着"产生的 `lifting +5/步`在阶段3/4 **还在发钱**,和放置竞争——**"抓住不放"本质就是这个没关掉的持续抬起奖励**。

**③ "一路不关、累加到第四阶段,不就和现在一样了吗?"** —— 这一步推理最关键,**基本完全正确**。

课程"不关闭、逐步打开"到最后是**四阶段全开**,这个**最终奖励配置就等于我们现在"一开始就全开"的设计**。区别只在训练日程:

```
课程式: 阶段1开 → 加2 → 加3 → 加4   (逐步打开)
我们:   1234 一开始就全开            (一次打开)
        └──── 最终落点:四阶段全开,完全一样 ────┘
```

**课程只改变"训练中按什么顺序打开奖励",不改变"最终奖励地形"和"局部最优陷阱在哪"。** 它能让优化更顺(早期没后阶段分心,更容易先把抓取学扎实、落进好的解区域),但**消除不了**最终地形里的陷阱。所以到第四阶段,面对的是同一个问题。

**④ "每阶段奖励设上限,能不能打破局部最优?"** —— 方向对,但我们实测一封顶就翻车。

先厘清:奖励**单步有界**(tanh 饱和,lifting 每步最多 +5),但**整段累计 = +5/步 × 赖着的步数**,靠"待得久"堆分。"设上限"= 把持续发分改成**饱和/一次性**,确实能砍掉"赖着刷分"的诱因——**是正确的一类解法**。但实验里这正好是 v14 vs v15 的对比:

| 版本 | 抬起奖励 | 结果 |
|---|---|---|
| **v14** | 持续发(continuous) | **赖着不放**(hover 悬停刷分) |
| **v15** | 一次性/封顶(≈设上限) | **塌掉**(抬一下马上松手,方块掉) |

**一封顶,失败模式从"不放手"翻转成"放太早"。** 因为上限同时砍掉了两样:一是"赖着刷分"的诱因(这是想要的),二是"搬运途中保持举着"的动力(这是不想要的)。抬起奖励一封顶,"继续举着"不再发分,若**下一阶段奖励没无缝接力把它拉走**,机械臂就"举着也没分了,松手算了"→ collapse。核心矛盾:**持续发→赖着不放;一封顶→放太早**;难点在"封顶瞬间的阶段接力"极难调。再加上**空中目标**(z=0.2~0.35)这个根因——"举着=对准目标"——上限也砍不掉。

**5g 总结**:课程/上限这些都是**正确直觉、正确方向**,但都不是"一行改动"能解决:① 硬顺序课程会遗忘+切不开;② 软课程累加到底就**等于现在的设计**,只改训练顺序不改地形;③ 奖励上限会把"不放手"翻成"放太早",需要**封顶 + 阶段平滑接力 + 把空中目标降到桌面 + 从头重训**一起上,才可能真正打破"抓住不放"。**记住那条贯穿始终的规律:局部最优由"奖励地形"决定;改训练顺序/课程能帮优化绕开,但消除陷阱必须改地形本身(奖励形状、门控、目标位置)。**

## 6. PPO 训练循环

### 6a0. 神经网络与 PPO 是什么关系(它是不是 DNN)

先厘清两个最容易混的概念,组会上常被追问:

- **神经网络 = 决策的"大脑本体"**:一堆权重参数,负责把观测变成动作。它是"被训练的对象"。
- **PPO = 训练这个大脑的"教学法"**:一套更新权重的规则(强化学习算法)。它是"训练的方法"。

比喻:网络是**学生**(一张白纸,随机初始化),PPO 是**教学法**(看到一段成功/失败的经历后,该怎么调这张白纸)。换个教学法(SAC、TRPO、A2C),同一个网络也能训,只是更新规则不同。所以**PPO 确实是强化学习算法**,属于策略梯度 / Actor-Critic / On-policy(同策略)一类;"近端"指它每次更新不让新策略偏离旧策略太远(clip 限幅),避免一步毁掉已学会的东西。

**这个网络是不是深度学习里的 DNN?** 是——精确说是 DNN 的一种:**MLP(多层感知机)**。包含关系:

```
深度学习
 └─ DNN(泛指"多层隐藏层"的网络)
      ├─ MLP  全连接层堆叠  ← 本项目 Actor/Critic 就是这个
      ├─ CNN  卷积网络      ← 本项目 ResNet18 属于这类(感知用,已弃用)
      ├─ RNN  循环网络
      └─ Transformer ...
```

本项目 Actor/Critic 是 MLP:输入 ~28 维观测 → 全连接 `256→128→64`(ELU)→ 输出 6 维动作,三层隐藏层、全连接、无卷积无循环,是最经典的 DNN 形态(3 层在现代标准里偏浅,但结构上确属 DNN/前馈网络)。对老师可表述为:**"一个多层感知机(MLP),属于深度神经网络(DNN)的一种。"**

【注意】 本项目其实有**两类不同的网络**,别混:

| 网络 | 类型 | 用途 | 训练范式 |
|---|---|---|---|
| Actor / Critic | **MLP**(全连接 DNN) | 决策:观测→动作 | **强化学习**(PPO) |
| ResNet18 | **CNN**(卷积 DNN) | 感知:图像→方块坐标 | **监督学习**(MSE 回归,已被颜色掩码取代) |

三者怎么串(一个训练循环):**网络(Actor)**产生动作 →**环境+奖励函数**给分 →**PPO**把"得分"翻译成"权重往哪挪、挪多少"→ 改 Actor/Critic 权重。注意奖励函数不是网络的一部分,也不是 PPO 改的对象;PPO 只改网络权重(见 6d)。本章后面的超参(clip/lr/γ/λ/熵系数…)全在描述**PPO 这套教学法**,而 `[256,128,64]` 描述的是**被教的网络**——两者正交。

### 6a. PPO 是什么(一句话直觉)

PPO(Proximal Policy Optimization,近端策略优化)是一种策略梯度算法:
> 让机械臂用当前策略去试很多次,把"比平均预期更好"的动作概率调高、更差的调低;但每次更新**幅度受限**(clip),不让策略一步跳太远而崩掉。"近端"就是这个"小步走"的意思。

它有两个网络:
- **Actor(演员)**:就是策略,输入观测输出动作(的概率分布)。
- **Critic(评论家)**:输入观测,预测"从这里开始预期能拿多少总奖励"(价值函数 V),用来判断某个动作是"比预期好"还是"差"。

### 6b. train.py 做了什么(`scripts/rsl_rl/train.py`)

1. 启动 Isaac Sim,按 `--task` 创建环境(默认 4096 个并行)。
2. 建 `OnPolicyRunner`(RSL-RL 提供),里面是 Actor-Critic 网络 + PPO 算法。
3. 若 `--resume`,加载 checkpoint 继续训练(我们的 warm-start 就走这条:`train.py:217-221`)。
4. 反复执行:**收集数据(rollout)→ 算优势 → 多轮更新网络 → 存 checkpoint**。
5. checkpoint 存到 `logs/rsl_rl/<experiment_name>/<时间戳>/model_xxxx.pt`。

> 【图】 **本章配图见 `数据流框图.md` 图7(PPO 训练循环与超参)**:把每个超参数标注在它在算法里起作用的位置。

### 6c2. ★PPO 公式逐项拆解:每个符号、每个超参的含义与取值来由★

> 6c 列了超参,这节解释"这些超参到底活在哪条公式里、每个符号什么意思、值是怎么定的"。按"学习时的自然顺序"从终点往回讲。

#### ① 最终目标:所有公式只为这一个式子服务

PPO 唯一真正想最大化的,是"一整回合的期望折扣回报":

```
max  J(θ) = E[ G_0 ] = E[ Σ γ^t · r_t ]
 θ                         t=0…T
```

- `θ`:Actor 网络的全部权重(要找的未知数,几万个数,最终存进 `model_26994.pt`)。
- `J(θ)`:用这组权重,平均能拿多少回报,越大越好。
- 后面所有公式(A、clip、各损失)**都只是为了"安全、稳定地"逼近这个 max,没有别的目的**。

#### ② 回报 G_t:从 t 步"往后"加,不是"至今"

```
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + … + γ^(T-t)·r_T
```

- 是从第 t 步**当下及以后**的折扣奖励和,**不是**过去 0~t 的累加。
- 原因:评价一个动作好不好,看它带来的**未来**;过去的奖励是"沉没成本",与"现在这个动作值不值"无关。
- 必须和 Critic 的 V 同方向(都往后看)才能相减比较。
- 口诀:**G_t 是"今后",不是"至今"。**

#### ③ 为什么 G_t 通常"拿不到",要用 GAE

两个原因:

1. **算不出来(工程)**:配置 `num_steps_per_env=24`——每攒 24 步就更新一次,**不等回合跑完**。我们一个回合最长 `episode_length_s=8.0`、控制周期 `sim.dt×decimation=0.01×2=0.02s`,即 `8.0/0.02=400 步`。24 步几乎必然在抓取**中途**被截断,后面的 r 还没发生,G_t 的尾巴被切掉。
2. **不好用(统计)**:就算跑到底,G_t 也是**单条随机轨迹的一次性样本**——往后几百步每步都有探索噪声,方差极大,当方向盘会乱抖。

解决 = **bootstrapping**:在截断处用 Critic 的 `V` 接住没跑完的尾巴。GAE(广义优势估计)就是这套折中:

```
A_t = Σ (γλ)^l · δ_{t+l}        δ_t = r_t + γ·V(s_{t+1}) − V(s_t)
```

- `δ_t`(TD 误差):"走一步后的新估计 [r+γV']"减"走之前的旧估计 V"。**注意 γ 只乘 V(s_{t+1}),不跨过减号去乘 V(s_t)**——折扣只打给未来,V(s_t) 是当下基准不打折。这来自贝尔曼方程 `V(s_t)=r_t+γ·V(s_{t+1})` 的移项。
- `λ=0.95`:在"信实际回报(准但抖)"和"信 V 预估(稳但偏)"之间折中。

> **为什么 horizon=24 而不是 400(整回合)?** 设 400 虽能拿到完整 G、偏差小,但:① 更新频率掉到 1/17(学得慢)② 批量大 16 倍(`4096×400≈164 万`,显存易爆)③ 策略纠偏被拖后。24 步配 GAE 的 bootstrapping,在"更新够频繁 + 数据够稳 + 显存够用"之间取平衡。**horizon 不必等于回合长度,这正是 GAE 存在的意义。**

#### ④ 策略其实是"高斯分布",动作是抽样来的(最该补的一层)

Actor 输出的**不是动作,是一个高斯分布的均值 μ**,配一个可学习的标准差 σ:

```
Actor(obs) → μ(6维)         真正的动作 a ~ N(μ, σ²)   从分布里"抽"一个
```

- 训练时从分布抽样 → 带探索噪声 → 才能试错;推理时直接取 μ → 行为稳定。
- `σ` 初值就是 `init_noise_std=0.28`。某个具体动作 a 的"概率",是把 a 代进高斯密度公式得到的**钟形曲线在 a 点的高度**:

```
 π(a|s)
   |        _-^-_     <- 峰值在 μ(网络最想做的动作)
   |      _-     -_
   |  a1 *         * a2
   |____-___________-____  -> 动作 a
          μ
  a1 离 μ 近 -> π 大(常被抽到)   a2 离 μ 远 -> π 小(很少被抽到)
```

> 连续动作下这是**概率密度**不是 0~1 的概率(单个精确动作的概率严格为 0,数值甚至可 >1);有意义的是下面的**比值**。6 维动作的概率 = 6 条钟形高度相乘(代码里用 log 概率相加)。

#### ⑤ 概率比值 r(θ):同一动作在新旧两条钟形上的高度比

```
        π_θ(a_t | s_t)        新策略给这个动作的概率(密度)
r(θ) = ──────────────────  = ───────────────────────────────
       π_θ_old(a_t | s_t)     旧策略给这个动作的概率(密度)
```

- μ 往这个动作 a 靠 → 新钟形在 a 处更高 → `r>1`(新策略更爱它);μ 远离 → `r<1`。
- PPO 不是直接写"概率+10%",而是挪 μ(改网络权重),让钟形靠过去,r 自然变化。

#### ⑥ Actor 损失:PPO 招牌,clip 是"刹车"

```
L_actor = − E[ min( r(θ)·A_t ,  clip(r(θ), 1−ε, 1+ε)·A_t ) ]      ε = 0.2
```

- `r·A`:朴素策略梯度——A>0 的动作想让概率涨、A<0 想让它跌。
- `clip(r, 0.8, 1.2)`:把概率比值死死卡在 [0.8,1.2],**一步最多变 ±20%**。
- `min(…)`:专防"贪心过头",A 再大也不让概率一次涨太多。
- 开头 `−`:优化器只会最小化,而我们要最大化回报,取负转换。
- **为什么非卡不可**:PPO 是 on-policy,旧数据只在"策略没大变"时才可信;一步跳太远会用错配的旧数据把好策略冲垮(对应 v17–19:v9 稍大步微调,grasp 44%→0)。这就是 "Proximal/近端" 的由来。

#### ⑦ Critic 损失:让预估 V 准(另一处 clip 在这)

```
L_critic = E[ ( V_θ(s_t) − G_t )² ]
```

- 纯回归(MSE):预估 V 越偏离实际回报 G,罚越重。Critic 越准,A 的基准越稳。
- `use_clipped_value_loss=True` 是**第二个 clip**:裁的是 **V 的变化量**(新 V 离旧 V 别跳太远),和 Actor 那个 clip **共用同一个 ε=0.2,但作用对象完全不同**(Actor 裁概率比值 r,Critic 裁价值变化)。

#### ⑧ 熵 H(π):给"探索"发津贴,防过早卡死

```
L = L_actor + c1·L_critic − c2·H(π)        c1=1.0(value_loss_coef), c2=0.0025(entropy_coef)
```

- **熵 = 动作分布有多"乱"/多不确定**。在我们这套高斯策略里,熵就等于钟形的胖瘦:`σ 大→熵高→敢探索`,`σ 小→熵低→很笃定`(对高斯,`H=0.5·log(2πe·σ²)`)。
- 熵前带**负号**:最小化 L → 反而最大化 H → 等于**奖励"保持高熵、别太快变笃定"**,拖住 σ 别过早缩没,防止过早收敛到局部最优(如"抓住不放")。
- `c2=0.0025` 取很小:给一点温柔的探索压力,又不盖过 Actor/Critic 两个主损失。

#### ⑨ 反传 + Adam(通用步骤,非 PPO 独有)

```
g = grad(L)              反向传播,算 L 对每个权重的梯度
g ← clip(g, 0.5)         梯度裁剪 max_grad_norm,防爆炸
θ ← Adam(θ, g, lr=5e-5)  按梯度更新权重
若 KL(新||旧) > desired_kl=0.005 → 自动调小 lr(schedule="adaptive")
```

**L 算出来之后到底怎么用?Adam 又在干嘛?** 关键澄清:**Adam 处理的不是 L,而是 L 的梯度**,中间隔着"反向传播"。

- **L 的唯一用途 = 被求一次梯度。** L 是个标量("现在多差"),它本身不告诉你该调哪个权重;只有对每个权重求偏导 `g_i=dL/dw_i`,才得到"把 w_i 调大,L 会变大还是变小、变多快"。`g_i>0`→该减小 w_i;`g_i<0`→该增大;`|g_i|` 大→该多动。**求完梯度,L 这个数字就功成身退了。**(这也是三项损失必须先加权求和成"一个" L 的原因:只有一个标量对一堆权重才能逐个求偏导。)
- **L → 梯度,是"反向传播"干的,不是 Adam。** 反向传播 = 链式法则,从 L 出发顺着网络一层层往回推,算出每个权重的 `dL/dw`。任何优化器(SGD/Adam)拿到的都是这同一张梯度表,**Adam 的工作从这之后才开始**。
- **中间插一道梯度裁剪**(`max_grad_norm=0.5`):梯度交给 Adam 前,若整张梯度表"长度"超 0.5 就等比缩小,防梯度爆炸把权重踹飞;方向不变、只压幅度。
- **Adam 怎么处理梯度——比"无脑减"聪明在两点。** 最朴素的 SGD 就一句 `w←w−lr·g`。Adam 给**每个权重**各维护两个记忆:
  ```
  m ← β1·m + (1−β1)·g      一阶矩:梯度滑动平均(方向的"惯性/动量")
  v ← β2·v + (1−β2)·g²     二阶矩:梯度平方滑动平均(这个权重一向多"陡")
  w ← w − lr · m / (sqrt(v) + ε)         (β1≈0.9, β2≈0.999, ε 防除零)
  ```
  1. **m(动量)= 平滑方向**:看最近一串梯度的平均,不只看这一次。梯度一直同向→加速冲过去;忽左忽右抖→互相抵消、不乱晃(像下坡带惯性)。
  2. **v(自适应缩放)= 给每个权重定制步长**:用 `1/sqrt(v)` 缩放——某权重一向很陡(v 大)→步子自动调小(别冲过头);一向很平/稀疏(v 小)→步子相对放大(别磨蹭)。**这就是 Adam 名字里 "Adaptive" 的含义**:几万个权重不再共用一个死步长,各有各的有效步长,所以比纯 SGD 收敛快、好调。

整条流水线:

```
① 总损失 L (标量,"现在多差")
        |  反向传播(链式法则)        <- 把 L 变成梯度,与优化器无关
        v
② 梯度 g = dL/dw  (每个权重一个,"各自该往哪调")
        |  梯度裁剪 clip(g, 0.5)      <- 安全阀,防爆炸
        v
③ Adam:动量 m 平滑方向 + sqrt(v) 定制步长
        |
        v
④ w <- w − lr·(...)   每个权重挪一点点 (lr=5e-5)
        |
        v
   策略略变好 -> 下一批数据重算 L -> 回到①,重复上万轮
```

> 一句话:**L 是"差多少",梯度(dL/dw,反传算的)是"每个权重往哪改",Adam 是"怎么稳着改"**(动量给方向、sqrt(v) 给步长)。Adam 全程没碰 L,只吃梯度。

#### ⑩ 这些超参的值是怎么定的?——常规默认 + 轻度对齐任务

**没有公式能解出唯一最优值**,它们都是手工设的超参,套路是"抄文献默认 → 按任务微调 → 看训练曲线验证":

| 超参 | 我们的值 | 含义 | 取值来由 |
|---|---|---|---|
| `γ` | 0.98 | 折扣/看多远 | 标准默认 0.99;`有效视野≈1/(1−γ)`,0.98→约 50 步,**有意往下压**以匹配抓取子动作的因果尺度(0.99 看 100 步偏远) |
| `λ` | 0.95 | GAE 偏差-方差折中 | GAE 论文标准默认,几乎从不动 |
| `ε`(clip_param) | 0.2 | 每步幅度上限 ±20% | PPO 原论文标准默认,常规范围 0.1~0.3 |
| `c1`(value_loss_coef) | 1.0 | Critic 损失权重 | 常规默认 |
| `c2`(entropy_coef) | 0.0025 | 探索津贴 | 常规小值,范围 0~0.01 |
| `lr` | 5e-5 | 每步改权重幅度 | v9 标定值(微调实验后恢复) |
| `desired_kl` | 0.005 | 自适应 lr 的 KL 目标 | 常规默认 |

> **关键认知**:`γ/λ/ε/c1/c2` 这类基本是"抄个常规值就工作得很好、不值得反复折腾"的超参(memory 里 v9~v19 调的几乎都是奖励权重和 lr,这几个一旦定下来就不碰)。它们的"正确性"只能靠训练曲线(reward 涨不涨、稳不稳)反过来验证。

#### 串起来:每条公式都在为最终目标打工

```
最终目标  max J(θ)=E[Σγ^t r_t]           <- 唯一想要的
   |  怎么逼近?
公式② G_t      未来奖励折现成"实际成绩"(往后看)
公式③ A_t      实际−预估=该升该降的方向       (γ=0.98, λ=0.95, 用V接住24步截断)
公式④ π/μ/σ    策略是高斯分布,σ=0.28 是钟形胖瘦
公式⑤ r(θ)     量出策略改了多少(新旧钟形高度比)
公式⑥ L_actor  按A更新,但clip限幅±20%        (ε=0.2)  *PPO核心*
公式⑦ L_critic 让V预估更准,A才可信            (c1=1.0, 第二个clip也在这)
公式⑧ L        三项合一,熵项保探索            (c2=0.0025)
公式⑨ Adam     反传更新权重                    (lr=5e-5, grad<=0.5, KL<=0.005)
   |
   └──> 改一点 θ,J(θ) 涨一点,重复上万轮 -> model_26994.pt
```

**一句话**:PPO 的最终目标只有一个——找一组网络权重让整回合期望回报最大。做法是用优势 A 指出每个动作该升该降(方向)、用 clip 把每步幅度卡在 ±20%(刹车),小步快跑地改权重。`γ/λ` 管"看多远",`ε` 管"步子多大",`c1/c2` 管"两网络与探索的配比",`lr` 管"每步改多狠"——所有参数都在伺候那一个 max J(θ)。

#### (补)这些超参会随训练加深而改变吗?——分清"超参"和"参数"

常见误解:"σ 训练中会变,那超参是不是都会随训练改?" **不对。绝大多数超参全程不变;真正一直在变的是"参数",而参数不叫超参。** 必须先分清这两个词:

- **超参(hyperparameter)**:训练**前**由人设定、用来**控制训练过程**的旋钮 → **基本全程不变**。
- **参数(parameter)**:被训练算法**自己更新**的东西(网络权重、σ)→ **每轮都在变**,但不叫超参。

> σ 会变,**不是"超参会变",而是 σ 本身就是个被训练的参数**——`init_noise_std=0.28` 只是设定它的**初值**,变它的是 Adam,不是"超参随训练漂移"。这是最容易混的一点。

按"变不变"分三类:

| 东西 | 训练中变吗 | 是超参吗 | 谁让它变 |
|---|---|---|---|
| `γ`,`λ`,`ε`,`c1`,`c2`,`num_steps_per_env`,网络结构… | **不变** | 是 | —— |
| Actor/Critic 网络权重 | 变(每轮) | 否(是参数) | Adam 按梯度更新 |
| σ 探索噪声 | 变(0.28 逐渐↓) | 否(是参数,**初值**才是超参) | Adam 按梯度更新 |
| 学习率 `lr` | 变(自动调) | 是(**唯一特例**) | adaptive 调度按 KL 调 |

- **第①类**:`γ/λ/ε/c1/c2/24步/网络结构` 等——设定后整个训练一个数都不动(就是公式⑩那批)。
- **第②类**:网络权重、σ——一直变,但变的原因是"被 Adam 按梯度更新",不是"超参随训练改";`model_26994.pt` 存的就是这一类的快照。
- **第③类(特例)**:只有 `lr` 因为我们设了 `schedule="adaptive"` 会自动调——`KL>desired_kl=0.005`(跳太狠)就调小 lr,反之调大。**但注意:即便是它,变的也只是 lr 这个数值,而控制它怎么变的 `schedule` 和 `desired_kl=0.005` 本身仍全程不变**;若设 `schedule="fixed"`,lr 也会恒定。

> **一句话**:超参是"训练前定死、控制训练的旋钮",几乎全程不变;真正一直变的是网络权重和 σ,但它们是被更新的"参数"不是超参(σ 会变只因它是参数,0.28 是其初值)。唯一会自动变的超参是 lr(adaptive 按 KL 调),但连它的调节规则本身也不变。

### 6d. 训练机制常见疑问(组会 Q&A)

**问: 4096 个机械臂里碰巧有几个成功了,失败的会学成功的吗?**
关键前提:**4096 个臂共用同一个策略网络(一个大脑)**,不是 4096 个独立学习者。每步所有臂的经验(成功+失败)汇成一批,PPO 用 Critic 估基线、算优势 `A=实际回报−基线`:成功→A>0→对应动作概率调高,失败→A<0→调低。更新后的策略下一轮同时控制全部臂。所以"是的",但不是臂抄臂,而是一个大脑从 4096 段经验里同时学;**失败样本也有用**(告诉策略别那么做),不能只留成功的。

**问: 能不能保留成功的臂、在此基础上接着练,形成良性循环?**
在 PPO 里"按臂筛选保留"不成立——只有一个共享策略、每回合全部重置,没有 per-arm 的东西可冻结;只留"碰巧成功"还会丢失败信息、过拟合运气、失去探索多样性。但这个直觉对应真实技术:① **warm-start / 微调**(保留好策略续训,我们就是从 model_26994 续训)② Self-Imitation / HER / 优先经验回放(重点回放成功)③ 课程学习 / reset-to-success ④ 进化算法 ES/GA(字面"保留成功个体",另一范式)。良性循环其实天然在发生(策略梯度把成功拉过来);注意边界:改了奖励地形再续训会 critic 失配而崩(v17–19 教训)。

**问: 日志里的分值是 4096 个臂取均值吗?**
是。`Episode_Reward/<项>`、`Mean reward`、`Mean episode length` 都是**对环境取平均**(reward_manager 用 `torch.mean(episode_sums[env_ids])`)。看到的是全体平均,不是某一个或最好的那个臂——所以它反映整体策略好坏。

**问: 每一轮训练修改的是什么?是权重吗?**
是——但是**神经网络权重**(Actor/Critic 这两个 MLP 里的连接系数,几万个数,外加探索噪声 std)。每轮:采样→算梯度→优化器(Adam,lr=5e-5)把每个网络权重往"好动作概率更高、价值更准"的方向微调一点;`model_xxxx.pt` 就是这堆权重的快照。【注意】 **别和"奖励权重"混**:奖励权重(+1.0/+5.0…)是人在代码里设死的"评分标准",训练**永远不改**;超参、物理引擎、观测/动作定义也都不变。训练唯一改的就是网络权重。

```

### 8c. ★颜色掩码识别详解★(配图见 `数据流框图.md` 图5)

这是我们最终采用、已验证可用的方案(基线抓取 32%)。它**不用任何神经网络、不用训练**,纯粹靠"方块是红的"这个先验,用几条简单的像素规则把方块从图里"抠"出来。分 5 步:

#### 第0步:先理解一张图是什么

固定相机拍出的是一张 256×256 的彩色图,本质是一个 **256×256×3 的数字矩阵**:每个像素有 3 个 0~255 的整数,分别是红(R)、绿(G)、蓝(B)三个通道的亮度。例如:
- 纯红方块的一个像素 ≈ `(226, 44, 40)`(R 很高,G/B 很低);
- 灰色桌面 ≈ `(175, 175, 175)`(R≈G≈B);
- 黄褐色机械臂 ≈ `(208, 196, 120)`(R 高,但 G 也高)。

#### 第1步:逐像素"是不是红?"→ 二值掩码(`play.py:399-403`)

对**每一个**像素,用三个条件同时判断它是不是"红":

```
是红   当且仅当   R > 110   且   R > G + 35   且   R > B + 35
        (够亮)      (比绿明显高)     (比蓝明显高)
```

逐条看它在排除什么:
| 条件 | 作用 | 谁被排除 |
|---|---|---|
| `R > 110` | 红通道要够亮 | 阴影里的暗像素 |
| `R > G + 35` | 红要明显比绿高 | **灰色桌面**(R≈G)、**黄褐机械臂**(R 只比 G 高 12,不够 35) |
| `R > B + 35` | 红要明显比蓝高 | 灰色桌面、偏蓝的高光 |

三个条件**同时成立**才算红。结果是一张**只含 True/False 的黑白图**(掩码):是红的像素=白,其余=黑。
> 关键:灰色(R≈G≈B)和黄褐色(R 不比 G 大 35)都过不了第 2、3 条,所以画面里**只有红方块会变白**。这就是为什么我们特意把方块改成纯红 `(0.9,0.08,0.08)`——让它成为画面中唯一"明显偏红"的物体。

#### 第2步:取最大连通域(`play.py:405-432`)

掩码里除了方块,可能还有零星几个被误判为红的噪点。**连通域**=把"上下左右相邻"的白像素聚成一团(像 Windows 画图的油漆桶填充)。把所有团找出来,**只保留像素最多的那一团**——那就是方块,零星噪点被丢弃。(算法是 4-邻接的 BFS 洪水填充。)

#### 第3步:求质心 → 方块的像素坐标

对保留下来的方块那一团,把所有白像素的坐标求平均:
```
x_质心 = 所有方块像素的列号的平均值
y_质心 = 所有方块像素的行号的平均值
```
`(x_质心, y_质心)` 就是方块在图像里的**像素位置**(比如第 28 列、第 34 行)。
> (数学上常把"平均值"写成字母上加一横,如 x / y,读作 "x-bar / y-bar";这里为避免字体缺字,直接写成 x_质心。)
> 若这一团太小(面积 < 10 像素,`play.py:437`),判为"没看到",`detected=False`,沿用上一帧的估计(就是你跑的时候看到的那条 `detection failed (area=...)` WARNING)。

#### 第4步:反投影,像素 → 机器人坐标(`_pixel_to_robot_xy`,`play.py:502`)

像素坐标 `(x, y)` 还只是"图上第几个点",要变成机器人能用的真实 xy。用**针孔相机模型**:已知相机的位置、朝向、焦距,从相机光心穿过该像素射出一条 3D 射线,让它和"方块所在高度的水平桌面"求交点——交点就是方块在机器人坐标系下的真实 (x, y)。(这一步把 2D 像素翻译成 3D 坐标。)

#### 第5步:写回观测,策略照常工作

把这个 (x, y)(z 用桌面高度)写进观测的 `object_position` 槽位(`play.py:822`),后面策略网络完全照常跑。

> **为什么这套简单方法反而比 ResNet 好?** 因为它不依赖训练数据分布——只要方块是红的、是画面里最大的红色块,它就能定位,光照/视角变化下"红"这个色相基本不变(这正是我们光照鲁棒性测试**零衰减**的原因)。代价是它依赖"方块必须是醒目的纯色",换成杂色物体就需要换识别方法。

> 三种模式对照:`gt` 跳过视觉直接用真值;`vision`=上面这套颜色掩码;`resnet`(`play.py:843-891`)用神经网络回归坐标,但有训练/播放图像域差(~6%),已被颜色掩码取代。

## 11. 评估指标:漏斗(funnel)

`funnel_v9.py` 把 `play.py` 导出的逐步 CSV 汇总成一个"漏斗",逐级判断:

```
总回合数
  └─ 抓起来          (方块抬升 > 3cm)              ← "抓取成功率"
       └─ 举着到过目标上方 (抬起期间 XY 距目标 < 5/8cm)
            └─ 放置成功      (结束时落桌 lift<1.5cm 且 XY 距目标 < 5/8cm) ← "端到端成功率"
```

> 为什么不用 `play.py` 自带的 3D `success`?因为目标点悬在空中(第 4c 章),3D 距离判定永远失败、恒为 0。漏斗改用**XY 距离 + 是否落桌**,才是真实的放置成功率。这个坑我们踩过两次,记在 `pick-place-goal-z-metric-mismatch`。

当前成绩(供参考):
- GT 模式抓取 ~35.6%,vision 模式抓取 ~32%(感知几乎不丢分)。
- 端到端放置(XY<8cm)~8~11%。
- 鲁棒性:光照免疫;杂物中度衰减;目标出训练框→搬运泛化失效;低摩擦→致命(策略靠"推-追"抓取,桌面变滑就追不上)。

## 12. 一句话串起全流程

> **训练**:4096 个仿真环境,用方块**真值坐标**喂给策略,PPO 反复试错、按一套分阶段奖励打分、小步更新网络,直到学会"给坐标就能抓-搬-放",存成 `model_26994.pt`。
> **推理**:加载这个模型,每 20ms 用固定相机拍照→红色掩码识别方块→反投影成坐标→写进观测→策略输出关节动作→机械臂执行,实时闭环,直到把方块放到目标区。
> **本质**:策略只认坐标不认图像;视觉只是推理时临时把"图像"翻译成"坐标"的一座桥。

## 13. 模型是如何被"调用"的(推理细节)

回答"机械臂如何调用模型"——分**一次性加载**和**每步调用**两段。

### 13a. checkpoint 文件里装了什么

`model_26994.pt` 不是"机械臂程序",它只是一包**神经网络权重**,包含:
- **Actor 网络**权重(策略本体:3 层 MLP `[256,128,64]`,输入观测 → 输出动作分布的均值)。
- **Critic 网络**权重(价值函数,推理时其实用不到,只训练时用)。
- **观测归一化统计量**(训练时记录的每维均值/方差,推理时要用同一套来归一化观测)。

### 13b. 开头一次性加载(`play.py`)

```python
runner.load(resume_path)                                   # play.py:285  把权重灌进网络
policy = runner.get_inference_policy(device=...)           # play.py:288  拿到一个"可调用对象"
export_policy_as_jit(...) / export_policy_as_onnx(...)     # play.py:309-310 顺手导出,供真机用
```

`policy` 是一个函数:**输入观测张量,返回动作张量**。它内部做的事:
```
obs ──▶ 观测归一化(减均值除方差) ──▶ Actor MLP ──▶ 动作均值
                                              (推理时直接取均值,不再加探索噪声)
```
> 训练时动作 = 均值 + 随机噪声(为了探索);推理时 = 只取均值(为了稳定、可复现)。这就是为什么同一 checkpoint + 同 seed 每次播放轨迹一模一样。

### 13c. 每个控制周期调用一次(主循环,`play.py` 约 957-970)

```python
# (前面已把方块坐标写进 obs 的 object_position 槽位)
actions = policy(obs)                  # play.py:965  ★调用模型,得到 6 维动作★
obs, rewards, dones, _ = env.step(actions)   # play.py:968  执行动作,物理推进一步
```

`env.step(actions)` 内部由 **Action Manager** 把 6 维动作翻译成机械臂指令:
- 前 5 维 → `JointPositionAction`:`目标角度 = 默认角度 + 0.5 × 网络输出`,送给关节的 PD 控制器去到位。
- 第 6 维 → `BinaryJointPositionAction`:≥0 张爪 / <0 合爪。

> **真机部署时**:不需要 Isaac,只要加载导出的 `policy.onnx`,自己写"拍照→识别→拼观测→`policy.run(obs)`→把动作发给电机"这个循环即可。逻辑和上面完全一样,只是把仿真的 `env.step` 换成真实电机指令。

## 14. ResNet 方案:我们标定了吗?训练了吗?(回答你的疑问)

**结论先行:标定了,也训练了。这是一个标准的"监督学习"。** 但最终部署没用它(用了更稳的颜色掩码),原因在 14d。

### 14a. 标签是"免费"的——仿真的最大红利

你担心"没标方块位置,模型怎么知道方块在哪"。关键在于:**在仿真里采集数据,标签是仿真器白送的**——仿真器本来就知道方块的精确坐标。看采集脚本 `collect_cube_pose_dataset.py:82-90`:

```python
obj_pos = object_asset.data.root_pos_w[:,:3] - robot_asset.data.root_pos_w[:,:3]  # 仿真真值
np.savez_compressed(out_dir/f"sample_{idx:06d}.npz",
    fixed_rgb = fixed_rgb,          # 输入:固定相机拍的图
    object_position = obj_pos_np,   # ★标签:方块的真实 xyz★
)
```

每个 `.npz` 样本 = **一张图 + 这张图里方块的真实坐标**。所以数据集是**带标签**的(只是标签不用人手标,由仿真器自动生成)。这正是"在仿真里训练再迁移到真机"这条路线的核心优势。

### 14b. 训练就是"看图回归坐标"(`train_resnet18_cube_pose.py`)

监督学习三件套:

| 要素 | 是什么 | 代码 |
|---|---|---|
| 输入 X | 固定相机 RGB 图(缩放到 224×224,标准化) | `:30-42` |
| 标签 Y | 方块真实 xy(取 `object_position[:2]`) | `:23` |
| 网络 | ResNet18(ImageNet 预训练)+ 末层换成输出 2 个数 | `build_model :47-56` |
| 损失 | **MSE 均方误差** = `||预测xy − 真实xy||²` | `criterion = nn.MSELoss() :126` |

训练循环(`:128-138`):反复地"喂图→网络猜 xy→和真值算 MSE→反向传播调权重",直到网络学会**从图像里看出方块在哪**。

### 14c. 怎么验证它真学会了(而不是瞎猜)

`evaluate_fit`(`:73-99`)算**相关系数 corr** 和 **R²**。这里有个关键陷阱:如果网络偷懒,**永远输出数据集的平均位置**,MAE 看着也还行,但 corr≈0。所以判断"真的在定位"要看 corr——我们的模型在数据集上 **corr≈0.92**,说明它在数据集上确实学会了看图定位。`:149-153` 还有自动告警:corr<0.8 就警告"别部署"。

### 14d. 那为什么最终没用 ResNet?(诚实交代)

模型在**数据集图片**上很好(corr 0.92),但**部署到 play 时**退化成了"猜平均值"(实际抓取仅 ~6%)。根因是**训练图像和播放图像有域差**(dataset 256×256 vs play 渲染细节差异等),网络没见过播放时的图像分布。

→ 所以我们**改用了颜色掩码方案**(第 8c 章):不学习、纯几何,固定相机看红方块→取红色连通域质心→针孔反投影。它不依赖训练数据分布,反而更稳(抓取 32%)。**ResNet 这条线训练成功但迁移失败,被颜色掩码取代。**

> 一句话对比:
> - **ResNet**:用"大量带标签的图"训练一个网络去**学**方块位置 → 受训练/部署域差拖累。
> - **颜色掩码**:不训练,直接用"红色"这个先验**算**方块位置 → 简单稳健,是当前采用方案。

## 16. 仿真用的是什么物理引擎?

### 16a. 是 NVIDIA 自己的 PhysX 5

Isaac Sim / Isaac Lab 底层的物理引擎是 **NVIDIA PhysX 5**(GPU 加速版),**是 NVIDIA 自家的引擎**,不是第三方的。
本项目代码里直接能看到它的配置(`lift_env_cfg.py:241-245`):

```python
self.sim.physx.bounce_threshold_velocity = 0.01            # 碰撞回弹阈值
self.sim.physx.gpu_found_lost_aggregate_pairs_capacity = 1024*1024*4   # GPU 接触对缓冲
self.sim.physx.gpu_total_aggregate_pairs_capacity = 16*1024
self.sim.physx.friction_correlation_distance = 0.00625     # 摩擦合并距离
```

`self.sim.physx.*` 这一串就是 PhysX 的求解器参数。**GPU 加速正是能同时跑 4096 个环境的关键**——所有环境的物理在显卡上并行求解,这是 Isaac 相对传统 CPU 物理引擎(如早期 MuJoCo/Bullet)的核心优势。

### 16b. 在 Isaac 里能不能换别的引擎?

**基本不能。** Isaac Lab 是**深度绑定 PhysX** 构建的——场景、关节驱动、GPU 张量化 API 都依赖 PhysX,没有"下拉菜单换成 MuJoCo/Bullet"这种选项。

你能调的是 **PhysX 的参数**(本项目就调了不少):
- 物理步长 `sim.dt`(本项目 0.01s = 100Hz)、渲染间隔;
- 求解器迭代次数(`solver_position_iteration_count` 等,见方块的 `RigidBodyPropertiesCfg`);
- 摩擦、回弹、接触缓冲区大小;
- 接触材质(我们的鲁棒性测试改的就是 `RigidBodyMaterialCfg` 的摩擦系数)。

**换引擎 = 换框架。** 如果一定要用别的物理引擎,就得换整个仿真框架:
| 框架 | 物理引擎 |
|---|---|
| Isaac Lab(本项目) | PhysX 5(GPU) |
| MuJoCo / MJX | MuJoCo |
| IsaacGym(旧) | PhysX |
| PyBullet | Bullet |
| Brax | 自研(JAX,GPU) |

> 补充:NVIDIA 也在推新的可微物理 **Newton/Warp**,未来 Isaac 可能支持,但当前本项目用的就是 PhysX 5。
```

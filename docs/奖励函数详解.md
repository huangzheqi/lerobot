# 奖励函数详解:代码 · 公式 · 并行机制

> 配合 `项目流程详解.md` 第 5 章阅读。本文给出**每个**奖励/惩罚函数的核心代码与数学公式,并讲清楚"是否同时计算""4096 个机械臂是否独立"。
> 代码位置:`pick_place/mdp/rewards.py`(分阶段项)与 isaaclab 内置(基础项),引用行号便于对照。

## 0. 先回答你的两个问题

### 0a. 这些得分是"同时"算出来的吗?——是

每一个控制步,Isaac Lab 的 **RewardManager** 会把当前注册的**所有**奖励项各算一次,然后加权求和。核心循环(`isaaclab/managers/reward_manager.py`):

```python
self._reward_buf[:] = 0.0                                  # 形状 (4096,)
for name, term_cfg in 所有奖励项:
    if term_cfg.weight == 0.0:        # 权重0的项跳过(如被关掉的 goal_tracking)
        continue
    value = term_cfg.func(env, **params) * term_cfg.weight * dt   # 形状 (4096,)
    self._reward_buf += value         # 累加到总奖励
    self._episode_sums[name] += value # 同时累计每项的回合总和(=日志里 Episode_Reward/<项>)
return self._reward_buf               # 返回 (4096,) 的每步总奖励
```

所以:**同一步里,15+2 个奖励项全部被算出 → 各自 ×权重 ×dt → 相加成一个标量(每个环境一个)**。它们不是先后、不是择一,而是并列计算后求和。

### 0b. 4096 个机械臂是独立计算的吗?——是,独立且并行

**每个奖励函数返回的是一个长度 4096 的张量**(`torch.Tensor`,形状 `(num_envs,)`),第 `i` 个元素就是第 `i` 个机械臂的得分,**只用到第 `i` 个环境自己的状态**。环境之间互不影响。

但它**不是用 Python 循环一个个算**的,而是用 **GPU 张量运算一次性把 4096 个一起算完**(向量化)。例如"末端到方块的距离":

```python
# p_ee, p_obj 形状都是 (4096, 3) —— 4096 个机械臂各自的末端/方块坐标
d = torch.norm(p_ee - p_obj, dim=1)     # 一次算出 (4096,) 个距离,GPU 并行
r = 1 - torch.tanh(d / 0.05)            # (4096,) 逐元素,每个环境独立
```

`torch.norm / torch.tanh / torch.where / 比较运算` 全是**逐元素**的:输入 (4096,…),输出 (4096,),元素 `i` 只依赖元素 `i`。这就是"既独立、又同时"——逻辑上每个机械臂独立打分,物理上靠 GPU 一步并行算完几千个。

> 一句话:**奖励项之间"并列相加",机械臂之间"并行独立"**。最终 RewardManager 吐出一个 `(4096,)` 的向量,喂给 PPO。

## 1. 通用约定与符号

- 所有函数返回形状 `(4096,)`(下面公式都是"对每个环境"而言)。
- `1[条件]`:指示函数,条件成立=1,否则=0(代码里是布尔张量转 float)。
- 记号:
  | 符号 | 含义 | 代码来源 |
  |---|---|---|
  | `d_eo` | 末端到方块距离 | `_ee_object_distance` |
  | `d_xy` | 方块到目标的**水平**距离 | `_goal_metrics` 的 `xy_dist` |
  | `z` | 方块高度(机器人系) | `obj.data.root_pos_w[:,2]` |
  | `v_z` | 方块竖直速度 | `obj.data.root_lin_vel_w[:,2]` |
  | `h_ee` | 末端高度 | `ee_frame...[...,2]` |
  | `θ_w` | 手腕 flex 关节角 | `_get_wrist_flex_joint_pos` |
  | `σ` | 夹爪张开比 ∈[0,1] | `_gripper_open_ratio` |
  | `L` | was_lifted 锁存 ∈{0,1} | `_cube_was_lifted_this_episode` |
- **门控**(`_gates`,阈值来自 cfg:`lift_height=0.045, near_goal_xy=0.06`):
  ```
  s1 = 1[z ≤ 0.045]                          (未抬起)
  s2 = 1[z > 0.045] · 1[d_xy ≥ 0.06]         (抬起 且 未到目标上方)
  s3 = 1[z > 0.045] · 1[d_xy < 0.06]         (抬起 且 到目标上方)
  ```
- **两种核函数**(把"距离/误差"变成"分数"):
  - `1 − tanh(d/σ)`:d=0 时=1(满分),d>>σ 时→0。用于"越近越好"。
  - `exp(−(x−x*)²/(2σ²))`:x=目标 x* 时=1,偏离越远越小。用于"越接近某目标值越好"(高斯钟形)。

## 2. 基础层(继承自 lift,isaaclab 内置)

### 【奖励】 reaching_object(权重 +1.0)
```python
return 1 - torch.tanh(d_eo / 0.05)
```
**公式**: r = 1 − tanh(d_eo / 0.05) **∈ (0,1]**
**作用**:末端越靠近方块,分越高。引导"先把手伸过去"。

### 【奖励】 lifting_object(权重 +5.0)
```python
return torch.where(z > 0.025, 1.0, 0.0)
```
**公式**: r = 1[z > 0.025] **∈ {0,1}**
**作用**:方块抬离桌面(>2.5cm)就给满分。这是训练时盯的"抓取健康度"。

### 【惩罚】 action_rate(权重 −0.1)
```python
return torch.sum(torch.square(action - prev_action), dim=1)
```
**公式**: r = Σ_j (a_j − a'_j)² **≥ 0**(乘负权重 → 惩罚)
**作用**:惩罚动作的突变,让运动平滑。

### 【惩罚】 joint_vel(权重 −0.1)
```python
return torch.sum(torch.square(joint_vel), dim=1)
```
**公式**: r = Σ_j v_j² **≥ 0**(乘负权重 → 惩罚)
**作用**:惩罚关节高速乱晃。

### 【关闭】 object_goal_tracking / _fine_grained(权重 = 0,已关闭)
原 lift 的"悬空目标跟踪",pick_place 用分阶段奖励取代,权重设 0 → RewardManager 直接跳过。

## 3. 阶段2:搬运(`_gates` → s2)

### 【奖励】 stage2_goal_xy_tracking_gated(权重 +10.0,std=0.12)
```python
return s2 * (1.0 - torch.tanh(xy_dist / 0.12))
```
**公式**: r = s2 · (1 − tanh(d_xy / 0.12)) **∈ [0,1)**
**作用**:举着方块时,离目标 XY 越近分越高。只在"已抬起且未到目标上方"激活。

### 【惩罚】 stage2_early_open_penalty_gated(权重 −5.0)
```python
return s2 * gripper_open_ratio   # σ
```
**公式**: r = s2 · σ **∈ [0,1]**(乘负权重 → 惩罚)
**作用**:搬运途中夹爪张开(σ 大)就扣分,防止半路松手掉方块。

## 4. 阶段3:下降(到目标上方后)

> 前两项用 `_gates` 的 s3;后三项用 `near_goal=1[d_xy<0.07]` 并额外乘锁存 L。

### 【奖励】 stage3_soft_descent_reward_gated(权重 +12.0,target_speed=0.04)
```python
return s3 * torch.exp(-(v_z + 0.04)**2 / (2 * 0.04**2))
```
**公式**: r = s3 · exp( −(v_z + 0.04)² / (2·0.04²) ) **∈ [0,1]**
**作用**:鼓励方块以约 −0.04 m/s **缓慢下降**(v_z=−0.04 时得满分);太快或上升都掉分。

### 【惩罚】 stage3_hard_drop_penalty_gated(权重 −8.0,max_down_speed=0.08)
```python
return s3 * torch.clamp(-(v_z + 0.08), min=0.0)
```
**公式**: r = s3 · max(0, −(v_z + 0.08)) **≥ 0**(乘负权重 → 惩罚)
**作用**:方块下落速度比 −0.08 m/s 还快(摔下来)才罚,越快罚越多。

### 【奖励】 stage3_ee_low_near_goal_gated(权重 +14.0,target=0.06, std=0.02)
```python
return 1[d_xy<0.07] * torch.exp(-(h_ee - 0.06)**2 / (2 * 0.02**2)) * L
```
**公式**: r = 1[d_xy<0.07] · exp( −(h_ee − 0.06)² / (2·0.02²) ) · L
**作用**:在目标附近时,末端降到约 6cm 高得满分。乘 L 防"不抬直接拖"。

### 【奖励】 stage3_object_height_near_table_gated(权重 +14.0,table=0.025, margin=0.018)
```python
return 1[d_xy<0.07] * torch.exp(-(z - 0.025)**2 / (2 * 0.018**2)) * L
```
**公式**: r = 1[d_xy<0.07] · exp( −(z − 0.025)² / (2·0.018²) ) · L
**作用**:目标附近时,方块降到接近桌面(2.5cm)得满分。

### 【奖励】 stage3_wrist_flex_release_pose_gated(权重 +2.0,target=−0.50, std=0.40)
```python
return 1[d_xy<0.07] * torch.exp(-(θ_w - (-0.5))**2 / (2 * 0.4**2)) * L
```
**公式**: r = 1[d_xy<0.07] · exp( −(θ_w + 0.5)² / (2·0.4²) ) · L
**作用**:目标附近时手腕摆到适合释放的姿态(约 −0.5 rad)。

## 5. 阶段4:释放(降到桌面后)

> 阶段4 各项用显式条件门控:`near_goal=1[d_xy<0.06]`、`obj_low=1[|z−0.025|<margin]`、`ee_low=1[h_ee<0.07]`。

### 【奖励】 stage4_release_reward_gated(权重 +12.0,margin=0.025)
```python
return 1[near_goal & obj_low & ee_low] * σ * L
```
**公式**: r = 1[d_xy<0.06  且  |z−0.025|<0.025  且  h_ee<0.07] · σ · L
**作用**:在"目标·低位·桌面高度"处张开夹爪(σ 大)→ 奖励放手。

### 【惩罚】 stage4_hold_too_long_penalty_gated(权重 −10.0)
```python
return 1[near_goal & obj_low & ee_low] * (1 - σ)
```
**公式**: r = 1[同上门控] · (1 − σ) **∈ [0,1]**(乘负权重 → 惩罚)
**作用**:到了该放的位置却还攥着(1−σ 大)→ 扣分,逼它放手。

### 【奖励】 stage4_gripper_open_near_table_gated(权重 +11.0,margin=0.02)
```python
return 1[near_goal & near_table & ee_low] * σ * L
```
**公式**: r = 1[d_xy<0.06  且  |z−0.025|<0.02  且  h_ee<0.07] · σ · L
**作用**:与 release 类似,低位近目标时张爪给奖励(门控阈值略不同)。

### 【奖励】 stage4_stable_placed_reward_gated(权重 +16.0,最大胡萝卜)
```python
return 1[d_xy<0.05 & |z−0.025|<0.015 & speed<0.08] * L
```
**公式**: r = 1[d_xy<0.05  且  |z−0.025|<0.015  且  ||v_obj||<0.08] · L **∈ {0,1}**
**作用**:方块**稳稳**(低速)放在目标 5cm 内、桌面高度 → 给最大奖励。这是整套任务的终点信号。

### 【奖励】 stage4_ee_away_after_place_gated(权重 +2.0,ee_min=0.08)
```python
placed = stage4_stable_placed_reward_gated(...)
return placed * torch.clamp((d_eo - 0.08) / 0.08, min=0.0)
```
**公式**: r = placed · max(0, (d_eo − 0.08)/0.08)
**作用**:放好之后,手离开方块越远奖励越多(避免放完还压着)。

## 6. 合成:每步总奖励

把上面所有项按 RewardManager 的循环合起来:

```
每步总奖励(每个环境) = Σ_项  ( 该项函数输出 × 权重 × dt )       , dt = 0.02s
                     = [ 1·reaching + 5·lifting + 10·s2_xy + (−5)·s2_open
                         + 12·s3_descent + (−8)·s3_drop + 14·s3_ee + 14·s3_obj + 2·s3_wrist
                         + 12·s4_release + (−10)·s4_hold + 11·s4_open + 16·s4_placed + 2·s4_away
                         + (−0.1)·action_rate + (−0.1)·joint_vel ] × 0.02
```

- 这一步对 **4096 个环境同时**算出 → 得到 `(4096,)` 的总奖励向量。
- 同时每项累加进 `Episode_Sums`,回合结束时输出到日志 `Episode_Reward/<项>`(详见 `项目流程详解.md` 第 7 章)。
- 因为有**门控**(s1~s4、near_goal、was_lifted),任一时刻**大多数项输出 0**,只有当前阶段的少数项在贡献分数——这就是"分阶段流水线"在数值上的体现。
